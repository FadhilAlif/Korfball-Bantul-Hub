## Database Schema (PostgreSQL / NeonDB via Drizzle ORM)

### RBAC & System Tables
```
users
  id, email, password_hash, full_name, is_active,
  email_verified_at, created_at, updated_at, deleted_at

roles
  id, name (unique), description, created_at, updated_at

permissions
  id, name (unique, format: resource:action), description, created_at, updated_at

user_roles          (junction: user_id → role_id)
role_permissions    (junction: role_id → permission_id)

refresh_tokens
  id, user_id, token_hash, expires_at, created_at, revoked_at

audit_logs
  id, user_id, action, resource_type, resource_id,
  details (JSONB), ip_address, created_at

notifications
  id, title, message, type, created_by, created_at
  + notification_roles  (junction: notification_id → role_id)
  + notification_reads  (junction: notification_id → user_id, read_at)
```

## Auth Flow

```
Register:
  Client → POST /api/auth/register
         → Validate (Zod) → Hash password (bcrypt)
         → Create user (is_active: false)
         → Send verification email
         → 201 Created

Login:
  Client → POST /api/auth/login
         → Validate credentials → Check is_active + email_verified_at
         → Create refresh token hash in DB
         → Sign accessToken (15m JWT with permissions) + refreshToken (7d JWT)
         → Set httpOnly cookies
         → Return user + roles

Token Refresh (automatic):
  Axios interceptor detects 401
         → POST /api/auth/refresh (sends refreshToken cookie)
         → Verify refreshToken hash in DB + not revoked
         → Rotate: revoke old, create new refresh token
         → Issue new accessToken cookie
         → Retry original request

Logout:
  Client → POST /api/auth/logout
         → Revoke refreshToken in DB (set revoked_at)
         → Clear both cookies
         → 200 OK
```

## Permission Inheritance

```
User
 └─► UserRole[] (many-to-many via user_roles)
       └─► Role
             └─► RolePermission[] (many-to-many via role_permissions)
                   └─► Permission { name: "users:read" }
```

When `GET /api/auth/me` is called:
1. Drizzle Query: User → UserRoles → Roles → RolePermissions → Permissions
2. Flatten all permission names into a string array
3. Frontend stores result in Zustand `authStore` (persisted)

Backend guard `@RequirePermissions("users:read")` checks permissions embedded directly in the verified JWT payload, or queries the active user permissions from DB if required.

## Request Lifecycle (NestJS)

```
Incoming HTTP Request
  │
  ├─► Helmet (HTTP security headers: CSP, HSTS, X-Frame-Options, nosniff)
  ├─► CORS middleware (origin whitelist, credentials: true)
  ├─► Cookie-parser (parse httpOnly cookies)
  │
  ├─► ThrottlerGuard (Global APP_GUARD via @nestjs/throttler)
  │     → Default: 60 req/min per IP
  │     → Sensitive Auth routes (@Throttle): 5 req/min per IP
  │     → 429 Too Many Requests if exceeded
  │
  ├─► JwtAuthGuard
  │     → Check for @Public() metadata
  │     → Read access_token cookie or Bearer header
  │     → Verify JWT signature + expiration
  │     → Attach decoded user payload to request
  │     → 401 Unauthorized if missing/expired
  │
  ├─► PermissionsGuard
  │     → Check for @RequirePermissions(...) metadata
  │     → Resolve user permissions via PermissionsCacheService (Redis / In-Memory TTL 10m)
  │     → Ensure user permissions satisfy required permissions
  │     → 403 Forbidden if permission is missing
  │
  ├─► ZodValidationPipe
  │     → Parse and validate DTOs against Zod schemas
  │     → 400 Bad Request with field error map if invalid
  │
  ├─► Controller & Service Layer
  │     → Execute business logic with Drizzle ORM transactions
  │     → Invalidate PermissionsCacheService automatically on role/permission mutations
  │
  ├─► AuditLogInterceptor (Global APP_INTERCEPTOR)
  │     → Triggered on RxJS tap() for routes decorated with @Audit(...)
  │     → Automatically redacts sensitive fields (password, tokens)
  │     → Saves structured entry via AuditLogsService
  │
  ├─► TransformInterceptor (Global Interceptor)
  │     → Wraps success response in standard ApiResponse envelope:
  │       { success: true, data: T, message: string, meta?: PaginationMeta }
  │
  └─► AllExceptionsFilter (Global Filter)
        → Maps NestJS / Drizzle / Zod errors into standard error response:
          { success: false, message: string, errors?: Record<string, string[]> }
```

## Progressive Web App (PWA) Architecture

- **Manifest**: Generated dynamically via `app/manifest.ts` providing standalone app metadata, theme color (`#3981f6`), and high-res adaptive/maskable icons.
- **Service Worker**: `public/sw.js` pre-caches application shell and offline fallback (`/offline`), serving static assets cache-first while strictly bypassing API routes (`/api/*`) and SSE real-time streams.
- **Registration**: Managed via client component `ServiceWorkerRegister.tsx` on root dashboard layout.
- **Outbox Storage**: IndexedDB storage layer isolated per browser context, preventing data loss when venue network connectivity drops.
